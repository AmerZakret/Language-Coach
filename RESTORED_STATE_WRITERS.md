# Restored-state write surfaces — C1-R2

## C2 extension

`SharedCommunityStorage` and `S3ObjectStorage` add immutable versioned PUT and logical DELETE. Both are inside the original admission and C1 nonexpiring permit. Independent `objects`/`object_events` persist preparation, intent, dispatch and completion across Mongo restoration; ambiguous remote acknowledgements preserve the permit. Owner-validated metadata callbacks establish deletion intent before commit. Cleanup cannot acquire authority from metadata absence or transfer A work into B.

`object-bootstrap-cli` and the configuration initializer are explicit new-empty operator actions, not runtime startup. `object-reconcile-cli` verifies a bounded exact-reference/version inventory while CLOSED/MAINTENANCE, adopts references and records an independent receipt without deleting or reopening. `object-effects-cli` processes one established same-timeline delete under OPEN authority; no background worker exists. The host isolation verifier additionally checks C2 private object topology and requires store/proxy restart after ambiguous work before minting recovery evidence. See [the complete storage contract](COMMUNITY_OBJECT_STORAGE.md). Existing global writer/history limitations remain unchanged.

This inventory covers repository entry points that can change Mongo domain/control data or retained uploads. The independent PostgreSQL authority, permit ledger and audits are outside Mongo restoration. Client caches, build artifacts and process-memory counters are listed separately. This is not an inventory of production deployments or historical credentials.

FULLY FENCED means cooperating required-mode application code, the existing Mongo transaction boundary and the completed restore barrier. It does not mean an atomic transaction across PostgreSQL, Mongo and the filesystem or protection from a privileged host/storage administrator.

## Other repository surfaces

- `inspect_db.js` and restore-consistency utilities read database records. The root inspector prints private fields and is never run by validation. Authority live preflight is database-read-only; an OPEN writable upload check is permit-bound and a CLOSED check performs no file writes.
- Test restore fixtures own fresh Mongo memory replicas or uniquely named synthetic databases. They are excluded from deployment artifacts. Explicit SQL corruption/rollback fixtures are tests, not exposed recovery endpoints.
- No persisted-domain background queue, cron or scheduled worker is present. Readiness polling is fenced above; abuse-control sweeping changes process memory only. Captured delayed/background callbacks are tested through the same transaction/file APIs and retain their original admission.
- Pronunciation reads bounded audio and uses disposable process/model memory and scratch space; it has no Mongo/retained-upload writer. No provider/model download is authorized by these tests.
- Web/Flutter persist local client queues/cache/identity and send HTTP mutations; they cannot reach PostgreSQL/Mongo. Server authorization/protocol v2 fencing remains mandatory. No client protocol change is part of R2.
- Lesson generation, Design/Vite, packaging, lockfile and quality scripts write source/build/test artifacts, not the retained Mongo/upload namespace. They must not be repurposed as runtime migration jobs.
- Arbitrary administrator sessions, historical binaries and external jobs are **OPERATOR-ISOLATED / NOT VERIFIED globally**. The disposable Docker verifier rejects unknown attached private-network endpoints and running/restarting project writers; it does not prove production credential revocation, orchestrator freeze, cross-host isolation or every historical deployment. Those limitations cannot excuse a new ordinary application bypass.

## Required evidence at restore time

Require a successful completed CLOSE with zero pending effects, stopped writer processes, disabled restart paths, no outstanding Mongo transactions, verified private-network inventory and a current isolation record. Resolve lost permits only through an administrator receipt after actual isolation and file reconciliation. Keep writes closed if any observation is missing or ambiguous. Independently verify PostgreSQL history continuity before authority recovery/reopening; an old consistent authority snapshot remains undetectable without an external freshness/history control.

The detailed live write-search inventory and final test results are recorded in the R2 verification report under `.release-validation/11bc1-r2`. No claim of shared uploads, absolute anti-rollback or multi-instance readiness follows.
